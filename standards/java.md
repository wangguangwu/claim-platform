# Java 开发规范

## 代码组织

- 后端模块必须遵守根需求的限界上下文、数据所有权和向内依赖分层；领域规则不得以跨模块工具类、跨库访问或共享实体的形式绕过边界。
- 生产 Java 类型应位于其职责对应的 `domain`、`application`、`adapter` 或 `infrastructure` 层；依赖方向不明确时先更新功能设计。
- 配置、持久化实现、消息适配器与外部系统集成不得泄露至领域模型。

## 注释与署名

- 每个生产类、接口、枚举、记录和 Spring 配置类必须有类级 Javadoc，说明职责、所属限界上下文或关键约束，并包含 `@author wangguangwu`。
- 每个有业务含义的 `public` 或 `protected` 方法、应用用例、领域服务、仓储端口、消息消费者、定时任务和外部适配器方法必须说明业务意图、关键前置条件、状态变化、幂等键或异常语义。
- 简单 Getter、Setter、构造器和显而易见的 DTO 映射无需重复注释；聚合根、状态机、补偿、并发与安全校验必须解释设计原因。

```java
/**

 * 确保相同租户与幂等键只形成一个申请事实。
 *
 * @author wangguangwu
 */
public class ApplicationSignCommandService {
}
```

## 测试与校验

- 修改业务行为时同步修改或新增测试；测试名称应体现业务场景、前置条件和预期结果。
- 修改后执行与改动范围相符的测试；准备合并或提交后端改动时执行 `mvn verify`，无法执行时在提交说明中说明原因和风险。
