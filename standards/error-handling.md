# HTTP 响应与异常处理规范

## 适用范围

适用于所有由 Gateway 暴露的 HTTP API、全局异常处理器、错误码和异常日志。稳定响应契约放在 `claim-common`；具体服务的异常映射器放在该服务自身，不能由另一个服务代替其处理异常。

## 响应信封

成功与失败响应统一使用 `ApiResult<T>`：

```json
{
  "success": false,
  "code": "REQUEST_VALIDATION_FAILED",
  "message": "请求参数不合法",
  "traceId": "...",
  "data": null
}
```

- `success` 表示请求是否成功；成功码固定为 `OK`。
- `code` 是稳定、面向调用方的机器可读错误码；领域错误码由所属限界上下文定义，不能复用技术异常类名。
- `message` 是可安全展示的说明，不能包含令牌、凭证、材料内容、跨租户数据、SQL 或堆栈信息。
- `traceId` 用于定位请求。网关或链路追踪已提供时必须透传；缺失时由服务生成并写入安全日志。
- `data` 仅在成功时返回业务数据；失败响应为 `null`。

## HTTP 映射与日志

| 场景 | HTTP 状态 | 错误码 | 日志要求 |
| --- | --- | --- | --- |
| 参数校验失败 | 400 | `REQUEST_VALIDATION_FAILED` | 记录字段名和 `traceId`，不记录原始敏感值 |
| JSON 或请求格式错误 | 400 | `MALFORMED_REQUEST` | 记录异常类别和 `traceId` |
| 资源不存在 | 404 | 上下文定义的错误码 | 记录资源类型与 `traceId`，不记录跨租户标识 |
| 状态冲突或幂等冲突 | 409 | 上下文定义的错误码 | 记录聚合类型、已脱敏标识和 `traceId` |
| 未预期服务端错误 | 500 | `INTERNAL_ERROR` | 记录异常类别和 `traceId`，响应不暴露内部信息 |

- 不得把异常信息、堆栈、SQL、外部系统响应原文或敏感请求体直接返回给调用方。
- 异常处理器不得吞掉异常后返回 HTTP 200；状态码必须表达失败类别。
- 全局处理器只处理边界异常映射，不承载领域决策、补偿或跨上下文编排。
- 每个新增领域错误码必须在所属功能 Spec 中说明触发条件、HTTP 映射、调用方行为与兼容性影响。
