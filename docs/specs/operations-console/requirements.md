# 运营管理台需求

## 项目背景与目标

平台需要统一管理端查看签收、材料、问题件、案件关系和推送执行情况。产品基线已定义六个前端功能域，但服务端契约尚未稳定；前端必须在稳定 API 之上提供操作与诊断入口，不能复制领域规则。

## 目标与非目标

- 建立 Vue 3 管理端，按 `sign`、`material`、`issue`、`case`、`push`、`tenant` 六个功能域组织。
- 支持签收查询、材料查看、问题件处理、案件查询、推送任务查询、推送记录查询和租户配置查看。
- 统一处理认证、`traceId` 回传、稳定错误码和可信租户上下文；局部依赖失败时显示已获得数据、失败来源和 `traceId`。
- 不在前端实现 Sign 状态机、幂等、补偿、租户协议解析、审核规则或保司推送规则；不直连领域服务、数据库、消息系统、OSS 或外部系统。

## 所属上下文与范围

- 前端项目固定为 `claim-platform-frontend/`，但不属于新的领域服务或查询服务。
- 本 Feature 依赖平台契约版本化及 Sign、Push 查询 API 的稳定定义；未交付的服务能力显示为不可用状态，不以客户端推测字段补齐。

## 验收标准

- 六个功能域的页面、路由、状态与 API 模块按业务能力组织，不按后端服务名组织。
- 所有请求通过网关客户端并统一携带/回传 `traceId`，错误信息不暴露敏感数据或实现细节。
- 签收和推送查询在分页、空结果、权限不足、局部失败与稳定错误码场景下可解释地反馈状态。
- 前端通过 `npm run typecheck` 与 `npm run build`。
