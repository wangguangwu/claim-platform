# 交付与可观测需求

## 项目背景与目标

工程启动能力只能解决本地运行；平台还需要可重复的构建、迁移、镜像交付和跨服务可观测闭环，才能在签收异步链路和案件推送失败时快速定位并安全恢复。

## 目标与非目标

- 建立后端、前端的持续构建与验证流程，阻止未通过门禁的改动进入交付物。
- 提供服务镜像、配置模板、数据库迁移执行与启动烟囱测试，确保环境可重复部署。
- 落地 OpenTelemetry、Prometheus、Grafana、Loki 的最小闭环，支持按服务、租户、状态和 `traceId` 定位。
- 为失败、重复消费、积压、补偿重发、限流和外部依赖异常提供可告警信号。
- 不新建业务服务、查询服务、任务表或执行历史表；不将敏感信息写入日志、指标、Trace 或告警。

## 所属上下文与范围

- 所属上下文：平台级交付与可观测能力；依赖 `platform-bootstrap` 提供的工程、Compose 与基础 Trace。
- 业务 DDL 仍由 Sign、Push Feature 分别拥有；本 Feature 只编排已交付迁移的执行、校验与回滚说明。

## 验收标准

- 后端修改自动执行 `mvn verify`，前端修改自动执行 `npm run typecheck` 和 `npm run build`，失败不生成可发布交付物。
- 镜像构建、配置校验、迁移、服务启动和健康检查组成可重复的部署烟囱测试。
- 可按服务、租户、签收状态、案件和 `traceId` 查询经过脱敏的 Logs、Metrics 与 Traces。
- 关键故障类别具备阈值、告警路由和可执行的定位信息，不包含敏感数据。
