# 签收内核需求

## 项目背景与目标

签收流程中变化最慢的部分是领域事实、状态机、幂等、数据约束和补偿语义。它们不应被首个租户协议或某个外部系统的报文变化拖动重做。本 Feature 建立 Sign 限界上下文的稳定内核；租户协议抽象、HTTP 边界、承保、审核和 OSS 协同由 [签收适配与协同 Spec](../sign-adaptation-collaboration/requirements.md) 承接，各真实租户的具体协议由该租户自己的接入 Spec 落地。

## 目标与非目标

### 目标

- 建立 `Sign`、`Material`、`ClaimIssue`、`CaseRelation`、`InteractionLog` 五个聚合及其不变量、8 态流转、终态保护、租户隔离和三层创建幂等。
- 以 Flyway 版本化 SQL 按架构基准 §3 的最终列交付 `claim_sign_db` 的五张表、唯一约束与逻辑关联索引（含问题件 `issue_no` 与 `ext_json`），不建立物理外键；问题件对外的定位名不进 DDL，由适配层映射到 `issue_no`。
- 落地发号、创建事务、业务锁、事实库回放、唯一键冲突回查和可查询的恢复入口。
- 为 XXL-Job 补偿注册签收服务执行器、补偿 Handler 与本地调度定义；未交付告警通道时按基线 §10 输出结构化恢复与超时信号。
- 为上层适配与协同提供不含外部协议 DTO 的命令、查询、事件发布端口和领域结果模型，并为事件发布端口交付日志级默认实现，使本 Feature 完成后服务可独立启动、独立通过门禁。

### 非目标

- 不实现 HTTP Controller、租户报文验签/加解密、`TenantAdapterRouter` 或具体租户 Pipeline。
- 不实现 RocketMQ Topic/Tag/消费者、承保/审核/OSS Adapter、问题件下发、审核回调、案件关系写入的外部消息入口或保司协同。
- 不定义外部字段、下游报文或外部错误映射；它们由平台契约 A 档确认后在适配与协同 Spec 实现。
- 不建立独立任务表、工作流引擎、执行事件历史表、事件 Outbox 表或生产告警通道；事件端口的默认实现只输出日志，不引入任何持久化。

## 核心业务规则

- `TenantContext` 是应用命令的唯一租户来源；内核不接受请求体、路径或查询参数中的 `tenantCode`。本地测试上下文只能由 `platform-bootstrap` 定义的 Gateway 开发测试凭证建立。
- `Sign` 的状态、不变量、终态保护、幂等语义、异步恢复边界和交互审计遵循基线与签收服务架构基准；内核不复制或改变这些长期规则。
- 创建事务原子提交 Sign、初始 Material 关系、初始状态与 `SIGN_SUBMIT` 交互日志。外部协同产生的交互日志独立提交，失败不回滚已经完成的外部副作用。
- 事件发布只通过应用端口表达；本 Feature 提供日志级默认实现，具体 MQ 路由与外部协同在完成契约确认后由适配与协同接入。发布失败由当前状态的补偿入口恢复，补偿不得直接改写业务状态。

## 所属上下文与范围

- 所属限界上下文：Sign；实现模块：`claim-sign-service`。
- 依赖 `platform-bootstrap` 提供 Maven、Flyway、MySQL、Redis、XXL-Job 运行基础和本地可信测试 `TenantContext`。
- 不依赖待确认的 HTTP、MQ 路由、外部系统报文或真实租户协议；因此可以在 `platform-contract-versioning` 的 B 档外部依赖未完成时实施。
- 本 Feature 交付的是可启动、可独立验证的内核，不是可被外部调用的系统：第一个可请求的签收 HTTP 入口与异步受理链路的端到端运行，都要等适配与协同在 A 档确认后交付；架构基准 §4.1 三层幂等同步创建链路的并发压测入口同样落在那之后。

## 验收标准

- 通过 Flyway 从空库创建五张签收表；不存在物理外键，`sign_no` 全局唯一，`tenant_code + external_apply_no` 业务唯一，`issue_no` 在 `tenant_code + sign_no` 范围内唯一，逻辑关联和审计检索列具有所需索引。
- 同租户同一 `externalApplyNo` 的串行与并发创建只回放同一事实；唯一键冲突能回查赢家；不同租户同号隔离。
- 聚合测试覆盖 8 态合法/非法流转、三类终态、撤销保护和问题件进出状态；应用测试覆盖创建事务整体提交或回滚。
- XXL-Job Admin、签收执行器、补偿 Handler 与本地调度定义均可运行；补偿只重发事件意图或调用幂等恢复端口，无法自动恢复时写出结构化信号与必要审计。
- 所有内核测试及 `mvn verify` 通过；不出现 Controller、外部报文 DTO、具体 MQ Consumer 或 Adapter。应用在只有日志级事件端口实现时可以启动，创建成功才表达事件意图、幂等回放不重复表达、端口失败不改变已提交事实与同步结果。
