# 平台契约版本化任务

## A 档：平台自决

- [ ] 起草签收、材料、问题件与撤销子资源的 HTTP 字段、鉴权前提、幂等键与稳定错误码触发条件，提交用户确认后回写 `baseline.md`。
- [ ] 起草 `SIGN_ACCEPT`、`ISSUE_REPLY`、`CLAIM_REVOKE` 的 Topic、Tag、消费者组、载荷版本、幂等键、重试与消费失败口径，提交用户确认后回写基线和签收架构基准。
- [ ] 起草问题件的对外定位字段名、消息载荷与多次打回场景下回复、补充材料的绑定语义，提交用户确认后回写签收契约；平台内部标识 `issueNo` 已按架构基准 §3 固定，本项不重新决定它，也不因此变更 DDL。
- [ ] 起草已登记外部失败类别到 `SignErrorCode` 的映射边界与调用方行为，提交用户确认后回写长期文档。
- [ ] 为已确认的 A 档 HTTP 与消息契约制定实现 Feature 的契约测试口径，并解除精确对应的 `sign-adaptation-collaboration` 任务。

## B 档：外部依赖

- [ ] 与审核、承保系统责任人确认真实报文、版本、幂等键、超时和错误映射；在确认前标记被阻塞的 Sign Adapter、Consumer 与测试项。
- [ ] 与租户系统责任人确认每个真实租户的验签算法、加解密方式、报文字段与凭证；未确认的租户不进入平台适配实现，协议到位后由独立的租户接入 Spec 承接，A 档平台自决项不代替它。
- [ ] 与内部案件系统责任人确认案件生成事件的归属、版本、载荷、顺序与幂等键；在确认前标记被阻塞的 Push 事件消费项。
- [ ] 与保司系统责任人确认推送、回执和状态同步契约；在确认前标记被阻塞的 `InsurerPushAdapter`、回执处理与测试项。
- [ ] 每次 B 档确认后回写相应架构基准和受影响 Feature；未确认项不得以默认字段、Topic 或 DTO 实现。
